# S1.12 — Livreur assigné

Ajoute `livraison.nom_livreur_snapshot VARCHAR(120) NULL` pour conserver le nom saisi lors de la mise en livraison. Le livreur n'est ni le destinataire ni l'administrateur auteur de l'action. Aucun compte livreur ou module RH n'est créé.

Migration additive, rejouable sous MariaDB 10.4. Les anciennes livraisons gardent NULL ; aucune identité n'est inventée. Les nouvelles mises en livraison exigent un nom de 2 à 120 caractères, validé serveur. Le journal conserve également ce nom lors de l'expédition et de la livraison.

Avant application manuelle : sauvegarde locale hors Git, vérification de la base cible `tout_y_est`, exécution hors transaction métier, puis contrôle de la colonne. Ne pas rejouer les anciennes migrations. Cette livraison de code n'applique pas la migration à la base navigateur.

Avant S1.12, l'affectation est indisponible et le serveur refuse une mise en livraison sans modifier commande/stock. Aucun rollback destructif automatique : supprimer la colonne après utilisation ferait perdre l'historique du livreur.
