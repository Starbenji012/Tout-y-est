# S1.10 — Numéros commerciaux progressifs

## Mécanisme

`numero_commande_sequence.numero` est un AUTO_INCREMENT InnoDB dédié, sans FK
vers commande. Il ne s'agit pas de l'identifiant interne de la commande.
Chaque création alloue un numéro dans la transaction S1.7 puis enregistre
`TYE-` + le nombre, complété à trois chiffres au minimum. La contrainte
`uq_commande_numero` reste inchangée.

MariaDB 10.4 (et MySQL 8) conserve le compteur AUTO_INCREMENT après rollback
et redémarrage. Les échecs peuvent laisser des trous : la séquence est croissante,
pas nécessairement continue. L'ordre d'allocation n'est pas forcément l'ordre de commit.
L'idempotence est vérifiée avant l'allocation : un retry réussi conserve son numéro.
Annulation, expiration ou suppression d'une commande ne suppriment jamais l'allocation.

## Application

Sauvegarder la BDD, suspendre les créations de commandes, puis appliquer le SQL
avant de déployer le code qui appelle cette table. Le script est rejouable :
il reprend les références numériques existantes et ne réinitialise jamais le compteur.
Sur une base sans référence numérique, la première allocation est 1.
Il ne modifie aucune commande, aucun snapshot, paiement ni stock.

Ne jamais TRUNCATE/DROP cette table, supprimer ses lignes ou réduire son
AUTO_INCREMENT en exploitation. Inclure cette table et son compteur dans les
sauvegardes/restaurations. Aucun rollback destructif automatique n'est fourni :
revenir à l'ancien code peut laisser la table en place sans risque de recyclage.

La référence commerciale n'est pas un secret : tous les accès restent protégés
par l'authentification et le contrôle du propriétaire, indépendamment du numéro.

Documentation : https://mariadb.com/docs/server/server-usage/storage-engines/innodb/auto_increment-handling-in-innodb
