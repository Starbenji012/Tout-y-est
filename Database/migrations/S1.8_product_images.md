# S1.8 — Images produit

Précondition : la table existante `image_produit` doit être vide. Si des données
existent, arrêter et préparer leur rattachement explicite avant la migration.
Ne jamais les supprimer ou déduire leur produit depuis les identifiants legacy.

Le DDL MariaDB/MySQL effectue un commit implicite : sauvegarder avant application.
Le schéma de référence crée directement la table finale sur une base neuve.
La clé générée nullable garantit au maximum une principale, sans limiter les secondaires.
La cascade supprime les métadonnées, pas les fichiers physiques.
L'ordre utilise un SMALLINT signé avec CHECK >= 0 : UNSIGNED seul peut ramener
une valeur négative à zéro lorsque le mode SQL strict est désactivé.

## Validation locale DEV uniquement

Le seed séparé `Database/seeds/checkout_image_test.sql` associe explicitement
`/assets/images/products/watch.jpg` au produit `dev-produit-checkout-usd`.
Cette montre est un visuel de TEST, pas une description commerciale du produit.
Le seed ne modifie ni les prix, ni le stock, ni les anciennes données DEV.
Ne pas exécuter ce seed en production. Ne pas rejouer le seed Checkout USD.

Les chemins acceptés par le service sont locaux, sous `/assets/images/products/`
ou `/uploads/products/`, avec une extension raster autorisée et un fichier existant.
Les URLs, traversées, chemins encodés et sorties par lien symbolique sont refusés.
